## How a job moves (your Orbit flow, from the git workflow docs)

Each job's work moves through these boxes:

1. **Your machine.** The job's worktree.
2. **Your fork.** `origin/<branch>`.
3. **The Moxie branch.** `moxie/<branch>`, reached by PR #1 from your fork.
4. **Staging.** `moxie/staging`, reached by PR #2.
5. **Main.** `moxie/main`, reached through the release PR #3 (`staging` → `main`), which carries every job in staging together.

Every task branch starts from `moxie/main`.

**Where a job is comes from its PRs, not from git ancestry.** PRs are squash-merged, so a branch's own commits never appear in staging. Checked on a real job: `feature/field-ops-damage-list`.
- PR #135 (fork → Moxie branch) and PR #136 (→ staging) are both merged.
- Yet its head commit is not in `moxie/staging`.

So:
- **In staging** = its PR #2 merged.
- **In main** = PR #2's merge commit is in `moxie/main`.

For a repo with no staging branch or no org remote, the map shrinks to fork → main.

## What each box shows

- **The job's box:**
  - title, crew member, stage and status (the words the Jobs list uses);
  - the branch;
  - **↑ ahead / ↓ behind `moxie/main`**;
  - commits not yet pushed to your fork, and uncommitted changes.
- **Each arrow:** its PR (number, open, draft, merged or closed), checks passing or failing, and review state.
- **Staging:**
  - jobs waiting there;
  - how far staging is ahead of main ("102 commits waiting for release");
  - the open release PR, if there is one.
- **Main:** its last commit and time.

The box a job has reached is highlighted. Clicking a job opens it in the usual three panes; clicking a PR opens it on GitHub.

## Steps

1. **`dashboard/lib/flow.js`, the server side.** For each repo with open jobs:
   - **Remotes:** the fork (`origin`) and the org (the `moxie` remote, or any remote whose address is the org's).
   - **Local counts (`git rev-list --left-right --count`):** each job against `moxie/main` and `moxie/staging`; unpushed commits against `origin/<branch>`; staging against main.
   - **PRs:** one `gh pr list --state all --json …` per org repo, matched by branch name.
   - **Pure functions** turn those facts into each job's position and the boxes, tested with tables.
   - **`FlowWatch` timing:**
     - every 10 minutes: `git fetch --prune` of both remotes (read-only), then the GitHub read;
     - every minute, and when jobs change: a local-only recount;
     - one refresh at a time.
   - **Routes and events:** `GET /api/flow`, `POST /api/flow/refresh`, and a `flow` event to the page.
   - **Demo:** invented flow data for its jobs; nothing touches the network.
2. **Notifications outside the browser (`dashboard/lib/notify.js`).** The dashboard itself sends them with terminal-notifier, so they arrive with the tab closed. Clicking one opens that job; macOS's built-in notifier is the fallback.
   - **Levels:**
     - **Needs you:** a go-ahead, question or permission; also a decision parked 4 h.
     - **Problem:** a reply that ended in an error, or the usage limit.
     - **Done:** a job reached staging or main, or was marked done.
   - **Each level** can be: sound, silent or off.
   - **Quiet hours** (off by default). Nothing pops while you are looking at the dashboard (the page says when it is visible).
   - **Settings:** a Notifications section with a Send test button and the last 50 notifications.
   - **No doubling:** the in-browser notifications step aside while these are on.
   - **Demo:** sends only the test.
3. **Home, full width (`#/`).**
   - The top bar gains **Map · Table · Desk** (Desk shows how many decisions wait).
   - **The map:** one section per repo, then lanes: job box → PR #1 → Moxie branch → PR #2 → staging → release PR → main. Staging and main are tall boxes on the right that every lane in that repo flows into.
   - **Beside the map:** the Foreman's "what needs you" (from the floor) and the cards waiting for an answer.
   - **The page header:** last refreshed, a Refresh button, and a filter (Open jobs · All · a repo).
   - **Play:** each lane shows its crew member (still, like the Jobs list).
   - **Play Off:** the same map without the crew.
4. **Table (`#/table`).** The same jobs as rows: job, repo, branch, level, stage, status, waiting on, ahead/behind main, PR #1/#2 state, age.
   - Sort by any column. Filter: Needs you · Running · Idle · In review (PR open) · Done. Search box. Enter opens the selected row; ↑ and ↓ move between rows.
   - The sort and filter are remembered in this browser.
5. **Desk (`#/desk`).** Every decision waiting for you across all jobs, in one queue: go-aheads (gate cards), questions and permissions, oldest first.
   - **Layout:** the queue on the left; the current item on the right, using the same gate, question and permission cards as the job page, with the job's latest brief.
   - **Keys:**
     - J / K: next and previous;
     - A: approve, or allow a permission;
     - D: deny a permission;
     - O: open the job.
   - After you decide, the next item opens. When the queue is empty: "Desk clear".
   - Hard lines and risky steps never get a one-key approve (as on the cards today).
6. **Tests and checks.**
   - node tests for flow facts → positions, `FlowWatch` timing, notifier levels, quiet hours and history;
   - Vitest for the map, table, desk and settings;
   - a demo walk-through of every new control;
   - screenshots;
   - an independent review.

**Not in this round:** health warnings and a New job button on each repo row (you didn't pick them), and merging from the dashboard (merges stay yours, on GitHub).

## Round 3: rows (Light, step 5, 2026-10-21)

The lane grid above ("super confusing": most cells empty dashed boxes, wide and tall) is gone. The map is now rows (`web/src/home/FlowMap.tsx`, the map part of `homeModel.ts`):

- **One row per job**: crew member, title, the **ship track** (worktree · fork · Moxie branch · staging · main as dots, filled up to `lane.reached`, discs for passed stops and rings for the rest, the finish-line flag ⚑ on the stop `settings.workflow.finishLine` means: PR #1 open/merged → Moxie branch, staging, main, none for "when I mark it"), one line of words (`whereLine`: where + the PR that matters, with its number linked), the counts as a muted suffix (`countsSuffix`), and one **next hint** on the right (`nextHint(lane, job, { repo, release, now })`: the Foreman's ask first, then the track's facts: commit, bring main in, push, open PR #1, checks failing, merge PR #1, waiting for a review on PR #2, open PR #2, waiting for the release, landed in main).
- **Groups** inside each repo's section: Needs you · Running · Idle (Paused with it) · Shipping · Done (folded; `fw.home.map.done`). The repo header carries the **release train** (`releaseLine`: "staging: 14 commits waiting · release #158 open · last release 2026-10-20 (#139)") and an "N aboard" disclosure listing the jobs in staging.
- **Tools above the rows**: chips with counts (All · Needs you · Shipping · one per repo when there is more than one; `fw.home.map.chip`), With recently closed (`fw.home.map.filter`, as before), Show: counts · branches (`fw.home.map.show`; counts on by default), the read time and Refresh.
- **Keys** (scope `map`, above `rows`): `j`/`k` highlight, `Enter` opens the job, `o` its newest PR, `/` the chips, `1`–`4` pick them. With no rows the keys fall through to the Jobs list's `j`/`k`.
- **Table**: a Shipping chip; the Where column uses the rows' words.
- **Jobs list rows** (§12): the stage chip only on a job that needs you.

Kept: `FlowView`/`FlowLane`, `useFlow`, the PR links, Refresh, the "what needs you" band. The one-row layout holds at 1000 px (the hint drops under the track) and is one line at 1440.
