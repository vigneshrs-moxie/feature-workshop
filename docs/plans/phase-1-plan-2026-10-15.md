## What you get at the end

- **Three panes:** a Jobs pane, a Foreman pane, and an empty Preview pane.
  - **Jobs pane:** grouped as Needs you, Running, Paused, Idle and Done.
  - **Foreman pane:** your messages, briefs, replies, routine steps, problems, and permission and question cards.
  - **Preview pane:** a placeholder with "Open in classic view" links until phase 4.
- **Composer:** Send, Steer, Interrupt and Pause. Each job keeps its own unsent draft.
- **Permission cards:** Allow once, Allow for this reply, Deny, and **Always allow…**. The last one shows the narrowest rule for you to edit, then confirm.
- **⌘K:** lists only the actions valid right now, plus the keys from design doc section 2. Mark done, Reopen, Options and History are reachable from ⌘K and the job menu.
- **New job sheet:** description, repo, kind, model, and an optional past conversation (absorbs today's History "Make it a job").
- **Usage-limit banner, Needs-you count** in the tab title, browser notifications and a chime.
- **Design tokens:** the dark theme from design doc section 9. The light theme comes in phase 6.
- **Shown only if present:** a brief's folded detail file, rulings and proof lines, from the workflow draft. When a job has none of these, nothing is shown and nothing breaks.
- **Hints for new teammates:** hover hints on every control, and one folded "How this works" box per pane that remembers if you closed it.

## Backend gaps found in the code (all additive; the old UI keeps working)

| Gap | Today | Phase 1 change |
|---|---|---|
| Serve the app | Only `public/` is served; no `/next` | Serve `web/dist` at `/next/` with an index fallback. Add MIME types for fonts and icons. Hashed assets can be cached. |
| One snapshot | The UI stitches 3–4 calls together | `GET /api/snapshot`: meta, jobs with a server-computed `group`, pending permissions, usage, and `seq`. |
| Live events | `change` carries no job and no sequence number; there is no replay | Envelope `{v:2,type,job,data,seq}` on a new `/api/events?v=2` stream, with a 500-event ring buffer and `Last-Event-ID` resume. The old stream stays as it is. |
| Thread updates | Every change refetches everything | `thread` events tagged with the job, so only that job refetches. Thread items get stable ids. The 60-item cap gets a "load older" option. |
| Steer | Not possible: sending while it runs returns 409 | Driver input becomes a queue. `POST /api/runs/:id/steer` and events for queued, delivered and acted on (see D1). |
| Pause and Interrupt | The same call | Two meanings (D2). |
| Always allow | Only "for this reply"; SDK suggestions stripped | Expose the suggestions. `POST /api/rules` saves to a dashboard rule list that `policy.js` checks (D3). |
| Stale cards | `permission-gone` isn't sent when a stop denies pending asks | Send it there too. |
| Usage live | Limit changes arrive only as a generic `change` | A `usage` event. |

## Decisions for you

*2026-10-15: D1, D3 and D4 approved as recommended. D2 revised below to one Stop button, awaiting a yes.*

- **D2 (revised) → rec: one Stop button instead of Interrupt and Pause.** Stop ends the current reply and the job waits for you. Drafts are always kept per job. "Paused" is used only for usage-limit pauses.
- **D1 Steer → rec: real mid-reply steering.** Your message joins the Foreman's live input and is read at its next turn (*queued → delivered → acted on*). The alternative holds it until the reply ends. That is simpler, but it is really "Send later".
- **D2 Pause vs Interrupt → rec:** **Interrupt** stops the current reply and the job stays Idle, ready for your next message. **Pause** does the same, moves the job to Paused, keeps your draft, and the job leaves Running until you resume. One flag; both resume the same Foreman session.
- **D3 Where "Always allow" saves → rec: the dashboard's own list** (`~/.feature-workshop/rules.json`). It is visible and removable in Settings, and only applies to dashboard-run jobs. The alternative, your `~/.claude/settings.json`, would also change terminal sessions.
- **D4 Classic links → rec: keep them until each phase replaces them.** "Try it on your computer", Details, Costs and History search stay in the old UI. The new UI links to the job's classic page.

## Steps (one commit each, branch `redesign/phase-1` off `main`)

1. **Scaffold** `web/`: Vite, React 19, TypeScript and Vitest, with base `/next/`. The dev proxy rewrites Origin so writes pass the guard. `npm run web:dev` and `web:build`. Nothing inline, to satisfy the CSP.
2. **Serve `/next`** from `server.js`, with MIME types and the cache header for hashed assets. Covered by a node test.
3. **Snapshot and v2 events:** `lib/events.js` (seq, ring buffer, resume), `GET /api/snapshot`, a server-side `group` field, job-tagged `thread` and `usage` events, and the `permission-gone` fix. Node tests.
4. **Design tokens and shell:** `tokens.ts` → `tokens.css`, the three-pane layout, the store hydrated from the snapshot and patched by events, reconnect resync, and the hash router.
5. **Jobs pane:** groups, rows (glyph plus label, stage, time, hue dot, "resumes 3:42pm"), the Needs-you count in the title, notifications and chime.
6. **Foreman pane, read side:** thread items with stable ids, BriefCard (headline, collapses once answered, optional detail fold), reply, routine-steps fold, problem, the live row, and "load older".
7. **Permission and question cards**, including the **Always allow…** draft-edit-confirm, the rules list in Settings, and `policy.js` reading it. Node and component tests.
8. **Composer:** Send with a preview (reusing `compose.js`), the model chooser, per-job drafts in local storage, Interrupt/Pause (D2), and Steer with delivery states (D1, driver queue). Fake query extended so Steer runs in the demo.
9. **New job sheet, ⌘K and the job menu** (Mark done, Reopen, Options, classic links), the usage banner and hints.
10. **Demo pass:** `npm run demo` drives the new UI on invented jobs. Then the gate items.
