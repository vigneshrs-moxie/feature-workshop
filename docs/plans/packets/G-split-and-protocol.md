# Packet G · The split and the protocol

**Goal.** Cut today's dashboard into a **runner** (the machine half: Foremen, job folders, locks, git, Try it, usage, the Orbit token) and a **site** (the web half: pages, routes, the event streams) that talk only through one small protocol, still in one process on `127.0.0.1:4477` (local mode, plan §2, §2.4). A job survives a service restart, because its state is the job folder, the audit log and a resumable Claude session (plan §1a "Harbor", §4.1 `resume`). This is the biggest refactor of v1.5 and every other v1.5 packet waits for it, so the bar is: nothing a person or a test can see changes (plan R2).

**Port 4481 · worktree `../ground-control-G` · branch `packet/G-split-and-protocol`. Runs alone: every other v1.5 packet depends on it.**

## What exists
- `dashboard/server.js` (about 2,350 lines) is both halves at once. At the top it builds the engine: `State` and `RuleStore`, the `Driver` (`lib/driver.js`, with `policyFor`, `goAheadFor`, `sessionSettings`), `LimitWatch`, `PlanUsage`, `LocalRunner`, `History`, `GateParking`, `FlowWatch`, `Notifier`, `Integrator`, the Orbit token store (`tokenStore`) and `OrbitInbox`, `UsageLog` and `TurnMeter`. Then the routes: the `GET` table and `routeGet`; `routePost` (`/api/jobs`, `/api/job/:slug/send`, `/gate`, `/takeover`, `/close` and `/reopen`, `/options`, `/policy`, `/local`, `/notes`, `/nudge/...`, `/repo`, `/api/runs/:id/stop` and `/steer`, `/api/permissions/:id`, `/api/settings`, `/api/rules`, `/api/usage/*`, `/api/play/*`); `routePut`; `routeDelete`; and the blocks `routeIntegrate`, `routeOrbit`, `routeTelemetry`. Then the event streams (`/api/events`, and `?v=2` through `lib/events.js` `EventLog` and `openStream`) and the screens server on `WIREFRAMES_PORT` (PORT+1). Writes go through `checkWrite(req.headers, { port, token })` (`lib/http-guard.js`); `TOKEN` is made at start.
- The environment the tests and Vignesh rely on: `PORT`, `WIREFRAMES_PORT`, `WORKSHOP_DEMO` (the fake query in `dashboard/demo/fake-query.js`), `WORKSHOP_STATE_DIR`, `WORKSHOP_FEATURES_DIR`, `WORKSHOP_PROJECTS_DIR`, `WORKSHOP_AGENTS_DIR`, `WORKSHOP_SKILLS_DIR`, `WORKSHOP_CLAUDE_PATH`, `WORKSHOP_CLAUDE_SETTINGS`, `WORKSHOP_GATE_PARK_MS`, `WORKSHOP_PLAN_USAGE`, `WORKSHOP_ORBIT_STORE`, `WORKSHOP_EXTRA_REPOS`, `GROUND_CONTROL_DIR`, `GROUND_CONTROL_ORBIT_URL`, `INTEGRATE_ROOT`. About twenty files in `dashboard/test/` spawn `node dashboard/server.js` with these and wait for its first console line.
- `Driver.start({ featureDir, slug, title, cwd, sessionId, model, text, kind, ... })` resumes a session when `sessionId` is given (`options.resume`), takes the job lock (`lib/lock.js` `acquire`) and gives it back when the reply ends. On SIGINT or SIGTERM, server.js stops every active run (`driver.stop`), so sessions stay resumable, but nothing resumes them on the next start. `State` (`lib/state.js`) keeps `sessions.json` (each job's session id, folder, model) and `audit.jsonl` (`send`, `run-ended`, `status_invalid`, …).
- `lib/orbit.js` `sessionEnv(store)` returns `{ ORBIT_FEEDBACK_TOKEN }` when a token is saved, but nothing calls it, so the Foreman's `orbit-feedback` MCP entry (header `Bearer ${ORBIT_FEEDBACK_TOKEN}`) has no value in the session. server.js writes that entry into `CLAUDE_SETTINGS_FILE`, which defaults to `~/.claude/settings.json`; whether Claude Code reads `mcpServers` from there is not confirmed (left open from v1).
- The close route (`/api/job/:slug/close`) calls `checkWorktree(f.worktree, f.repoPath)` and `removeWorktree(...)` without `jobDir`, so `lib/close.js`'s lock check (`heldElsewhere(jobDir)`) never runs. The job snapshot (`boardCard`, `jobDetail` in server.js) says nothing about the lock (left open from v1).

## Steps
1. **The protocol** (`lib/protocol.js`), two closed lists, frozen:
   - `REMOTE_COMMANDS`, all a site may ever ask of a runner (plan §2.4): `start` (a job), `reply`, `approve`, `send-back`, `stop` (the gate card's Stop), `allow`, `deny` (a permission), `pause` (stop a reply in progress), `take-over`, `fetch-diff`. Each with its fields and their checks (slug, text up to 20,000 characters, brief number, request id, note) and nothing else.
   - `LOCAL_COMMANDS`, what only the page on this computer may ask: `steer`, `resume`, `close`, `reopen`, `options`, `policy`, `notes`, `try-it` (the `/local` actions), `settings`, `rules`, `nudge`, `repo`, `usage-resume`.

   `parseCommand(raw, { from: 'site' | 'local' })` returns `{ ok: true, command }` or `{ ok: false, error }` in plain words: an unknown type, a local command from the site, an extra field or a wrong type is refused. `EVENT_TYPES` is what a runner sends up (§2.4: status, brief, document, gate card, permission card, evidence, cost, branch and PR names, lock, heartbeat, plus the run and steer states the page gets today). `makeEvent(type, data)` refuses unknown types, passes the data through `scrubDeep` (lib/orbit.js), and refuses data with a key named `diff`, `patch`, `env`, `token` or `source` (the "never carries" column of §2.4; `fetch-diff` answers go straight to the asker and are never events). One `PROTOCOL_VERSION` number.
2. **The runner** (`dashboard/runner/index.js`): `createRunner(opts)` builds the machine half that server.js builds today (the list under What exists, minus anything HTTP) and returns `{ handle(command), read, on(type, fn), start(), stop() }`. `handle` runs `parseCommand` first, then the same code the routes run today: move it, don't rewrite it. `read` is what the site reads in local mode (jobs, one job, its documents and thread, diffs, costs, usage, flow, Orbit status); in v2 these become mirrored records, so keep them plain functions that return data. Use plan §2.1's table to decide which half owns what.
3. **The site** (`dashboard/site/index.js`): `createSite({ runner, port, token, ... })` returns the request handler with every route that exists today, same paths, answers, status codes and headers. Every route that changes a job calls `runner.handle(...)`. Nothing under `dashboard/site/` imports `lib/driver.js`, `lib/local.js`, `lib/lock.js` or `child_process`. Move the routes as whole blocks into `routes-jobs.js`, `routes-settings.js`, `routes-orbit.js`, `routes-telemetry.js`, `routes-integrate.js` and so on, and mount them from one list in `site/index.js` so later packets add a file and one line. The event streams stay as they are, fed from runner events.
4. **The host** (`dashboard/server.js`): reads the same environment variables, makes the runner and the site, listens on `127.0.0.1:PORT`, starts the screens server on `WIREFRAMES_PORT`, prints the same console lines, and on SIGINT or SIGTERM calls `runner.stop()` (which pauses active replies, as today) before it exits. `npm start` and `node dashboard/server.js` work as before.
5. **Replay on restart** (`dashboard/runner/replay.js`). At `stop` the runner writes one audit line `service-stop` naming each reply it paused. At `start`, before the routes open, `replay({ state, featuresDir })` reads `audit.jsonl` and `sessions.json` and rebuilds, for each job not closed: its last session (id, folder, model, extra folders), whether a reply was cut off (a `send` with no `run-ended`, or one named in `service-stop`), its gate and its status-check count; then it writes one `service-start` line. A reply paused by a clean stop resumes by itself (`Driver.start` with its session id and the text "Ground Control restarted. Carry on from where you were."), once the job's lock is free and no usage limit holds (`LimitWatch`). A reply cut off by a crash (no `service-stop`) does not: the job shows as paused, with the thread note "Ground Control stopped while the Foreman was working. Resume to carry on." Each resume is an audit `send` with kind `resume-after-restart`.
6. **`ground-control resume <job>`** (`bin/ground-control.js`; `package.json` `"bin": { "ground-control": "bin/ground-control.js" }`). The running service writes `service.json` in the state folder (mode 600: pid, port, its write token) and removes it on stop (`dashboard/runner/service-file.js`). `resume <job>` takes a slug or a ticket key (`ORBIT-479`), reads `service.json`, checks the pid is alive, and posts the `resume` command to the service. With no service running it says: "Ground Control isn't running. Start it with npm start (ground-control start once it is installed). A job paused by a clean stop carries on by itself."
7. **The Orbit token in the Foreman's session (left open from v1).** The runner adds `env: { ...process.env, ...(await sessionEnv(orbitStore)) }` to the options `Driver` gives `query()`, so `${ORBIT_FEEDBACK_TOKEN}` in the MCP entry has a value. Never put the token itself in `mcpServers`, the prompt or an argument (arguments show in the process list). Then confirm which file Claude Code reads user MCP servers from, in a throwaway home only, never the real `~/.claude`: `HOME="$(mktemp -d)" claude mcp add --scope user --transport http gc-probe http://127.0.0.1:9/x`, see which file appeared, then remove it. Claude Code's own docs point to `~/.claude.json`; if that is what you see, change `CLAUDE_SETTINGS_FILE`'s default to it (`WORKSHOP_CLAUDE_SETTINGS` still overrides), and on the next token save move an entry left in the old file. Say in the hand-back what you found and how.
8. **The lock, end to end (left open from v1).** The close route passes `jobDir: f.dir` to `checkWorktree` and `removeWorktree`. The job snapshot carries the lock: each job card and the job detail get `lock: { owner, pid, branch, acquiredAt }` or `null`, from `heldElsewhere(f.dir)`. (The page that shows it is packet M.)
9. **Tests.** `protocol.test.js`: every command on each list is accepted with good fields; an unknown type, a local command from the site, an extra field and a wrong type are refused; `makeEvent` refuses unknown types and the never-carried keys and hides an `orbfb_` token. `replay.test.js`: from fixture audit lines, a clean stop resumes, a crash does not, a closed job is left alone, a lock held by a live process is respected. `restart-server.test.js`: a demo dashboard (`WORKSHOP_DEMO=1`, its own `PORT` and `WIREFRAMES_PORT` from a free port, as `finish-server.test.js` does) starts a reply that waits, gets SIGTERM, starts again on the same state folder and resumes the same session id, with `service-stop` and `service-start` in the audit; plus the grep that `dashboard/site/` imports no driver, local runner, lock or child process. Every existing test passes without one line changed.

## Acceptance
Local mode behaves exactly as before: every existing test in `npm test` and the web tests passes unchanged, and the pages look and work the same. A job survives a service restart: a clean stop resumes by itself, a crash shows Resume, and `ground-control resume <job>` resumes it. The command list is a closed enum with a test that rejects anything else. Each Foreman session has `ORBIT_FEEDBACK_TOKEN` when a token is saved, and the MCP entry is in the file Claude Code really reads. A lock held elsewhere stops the close route from removing the worktree, and the snapshot shows the lock. All tests green.

## Rules that apply to every packet (read once, obey always)

- **Base:** `main` of the Ground Control repo (today `~/Projects/feature-workshop`, to be renamed `ground-control`) after Vignesh has fast-forwarded `redesign/orbit-ready` into it. If `git log main..redesign/orbit-ready` is not empty, stop and tell Vignesh; do not base on `main` then.
- **Worktree and branch:** `git worktree add ../ground-control-<id> -b packet/<id>-<name> main` from the main checkout. Work only there.
- **Port:** run the dashboard with `PORT=<port> npm start` in the worktree. **Never use 4477 (Vignesh's live dashboard) or 4479 (his demo).** The screens server takes `<port>+1`.
- **Owned files only.** Touch nothing outside the "Owns" list. If you need a change elsewhere, write it under "Needs from others" in your hand-back and stop at that point.
- **Tests:** `npm test` (node:test, `dashboard/test/*.test.js`) and `cd web && npx vitest run`. Both green before hand-back. **No model calls in tests:** the server under test runs with a fake query (`WORKSHOP_DEMO=1`); never import the Agent SDK in a test.
- **Never push, never open a PR, never merge.** Commit locally, one commit per step, plain messages. Hand back the branch name and the last SHA.
- **Status is never shown by colour alone; themes change looks only; keys never fire while typing or with a dialog open.** Use the theme tokens, not literal colours.
- **Plain words** in every string a person reads. No jargon.
- **Hand-back format** (paste into the integration board's notes or tell Vignesh): packet id, branch, last SHA, what was done per step, test output tail, anything not done and why, "Needs from others".
