--risks
readOptions spreads raw file over defaults (options.js L104): a v2 options.json read by an un-updated dashboard or an older skill will carry `level`/`models` through but `flow` must still be present and sensible, or FLOWS[o.flow] lookups in describeOptions (L131), server.js L834 and skippedFor (L123) degrade silently to 'auto'.
normalize() is the single validator for both POST /api/jobs and POST /api/job/:slug/options and strips unknown keys; adding level/models there changes every options write and the first-message text (server.js L870) that the Foreman parses — the skill must be updated in the same release or the Foreman sees wording it does not know.
status-json.js warns on schema_version != 1 (L31) and features.js appends warnings to the job; if the skill starts writing schema_version 2 or new fields before the parser is extended, every job shows a warning; conversely, parseStatusJson tolerates unknown keys, so `suggested_level` can be added without bumping the version.
Brief 'answered' state is positional (thread.ts L55: any later 'you' item). A chip that appends a 'you' line through composeReply will mark the gate's brief as answered even though the gate decision itself was not made.
Thread item ids for audit-derived items are sha1 of the whole entry (thread.js L18); adding fields to existing audit actions (e.g. level on 'options') changes nothing retroactively, but changing the shape of an entry type alters ids only for new entries — safe, but any new gate card keyed on audit entries must not rely on ids across dashboard code changes to audit payloads.
Installed skill is a copy, not a symlink (~/.claude/skills/feature vs ~/Projects/claude-feature-workflow/skills/feature); phase 2's job-options.md edit must land in the workflow repo and be re-installed (install.sh) or the two drift; the dashboard has no way to detect which copy the Foreman reads.
FLOWS.large.model is Fable (options.js L26) and POST /api/jobs picks the Foreman model from FLOWS[flow].model when the sheet sends none (L834); mapping L3 -> large via the shim without pinning models.foreman would start L3 Foremen on Fable, contrary to decision #7.
The thread is rebuilt from all audit lines on every fetch (server.js L336, auditFor Infinity) and the audit file is one global append-only JSONL; adding chatty gate/level audit actions grows it and every refetch; mapping must be added in thread.js or new actions are invisible.
Demo mode drives the shell through fake-query.js only; without extending advance() to read options.json level and emit plan-stage status (questions, decided_on_your_behalf, artifacts with versions, suggested_level), gate cards and LevelCard cannot be exercised without real Claude usage.
